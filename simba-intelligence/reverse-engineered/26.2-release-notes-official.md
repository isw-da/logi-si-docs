## Summary

This release improves reliability, deployment flexibility, and day-to-day
usability across Simba Intelligence. Key updates include single sign-on with
Composer, support for task-based asynchronous data source agent runs that survive
page refreshes, broader deployment improvements for Helm and Kubernetes, expanded
model and provider options including Ollama and Bedrock-related enhancements, and
stronger handling of hidden fields, disabled capabilities, cache invalidation, and
timeout scenarios. The release also removes remaining Symphony integration
dependencies as Simba Intelligence continues as a Composer-aligned product
experience.

## New Features

- **Single sign-on with Composer** so users can move between Simba Intelligence and Composer with a more seamless authentication experience.
- **Async task-based Data Source Agent execution**, allowing long-running source generation to continue across page refreshes and making progress tracking more resilient.
- **Support for different LLMs by agent**, enabling more flexible model selection for query, source creation, and related AI workflows.
- **Retry support for chat responses**, giving users a way to re-run an unsatisfactory response with corrective guidance.
- **Composer feature-flag endpoint for the frontend**, allowing the UI to adapt automatically to active license capabilities.
- **Ollama support completion**, expanding local and air-gapped AI deployment options.
- **Prebuilt AMI deployment option** for environments that want a faster path to getting Simba Intelligence running.

## Improvements to existing features

- **Composer integration simplification** by removing remaining Symphony integration code and aligning deployments around Simba Intelligence with Composer.
- **Data source agent quality improvements**: validation of generated custom metric formulas, prevention of self-referencing joins, prevention of repeated joins to the same table, and limiting available connectors in the source-creation UI to supported types.
- **Query reliability improvements**: better handling of hidden fields, disabled field capabilities, source-scoped rules in final chat responses, and rule-aware cache behavior.
- **Performance improvements**: cached visual payloads, conversation history summarization and compaction, configurable Redis cache sizing, lighter statistics calls, timeout-tolerant stats handling, and asynchronous fetching where immediate value lookups are expensive.
- **Search and retrieval improvements**: moving toward targeted data source search instead of returning all data sources indiscriminately.
- **Deployment and platform improvements**: PodDisruptionBudgets in Helm, removal of the no-longer-needed MCP sidecar, GitHub Action build updates, upgraded MCP libraries, and automatic detection and cleanup of tenant-scoped vector indexes when embeddings change.
- **LLM platform improvements**: a Vertex AI embeddings workaround, Bedrock-related enhancements, short-term key support considerations, and broader maintainability and security hardening.
- **UX improvements**: a Composer UI link when visuals are enabled, and generated visual names for created visuals.

## Bug fixes

- Fixed AG Grid theme regressions on Connections and Data Sources pages after Composer image updates.
- Fixed field-identifier lookups timing out while fetching distinct values from Composer.
- Stopped error noise when clearing indexes that do not exist.
- Fixed cache invalidation gaps so semantic cache entries reflect data source and rule changes.
- Improved handling for statistics and distinct-value timeouts so failures do not derail query generation.
- Resolved cases where intentionally hidden fields could appear in generated requests.
- Resolved cases where fields with disabled capabilities could be used by AI-generated queries and visuals.
- Improved multi-tenant scheduled suggestion generation across tenant data sources.

## Breaking Changes

- **Symphony integration removed** from the product code path. Plan deployments as Simba Intelligence with Composer (bundled or separately deployed).
- **Legacy streaming Data Source Agent run endpoint deprecated** in favour of the task-based API flow. Existing functionality remains for now; new integrations should use the task-oriented pattern.
- **MCP sidecar container removed** from Helm deployments where no longer required.
