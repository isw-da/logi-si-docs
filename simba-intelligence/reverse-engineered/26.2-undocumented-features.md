# SI 26.2.0 — undocumented features, reverse-engineered for the KB

Reverse-engineered from a live 26.2.0 instance (azuretest, 2026-07-11): Flask
url_map, the app's own generated OpenAPI spec, chart diff vs 26.1.1, DB schema,
env vars and the MCP tool schemas — cross-checked against the public Mintlify
docs (whose Release Notes stop at 25.4 and whose `openapi.json` is a placeholder).

Build of record: `GET /api/v1/version` →
`{version: 26.2.0, git: 28c5ee9, db_version: 6c21df0a75ba, build_time: 2026-06-29}`.

## 0. The biggest find: the product ships its own live API spec

The main app serves a **complete Flasgger/Swagger contract** that the public
docs do not expose:

- `GET /apispec_1.json` — OpenAPI, title **"Simba Intelligence API"**, version
  **26.2.0**, **32 documented paths** across tags Agents, Agents (Experimental),
  Chat (Experimental), Data, File Analyzer, History, LLM Configurations, Rules,
  System, Task.
- `GET /apidocs/` — Swagger UI. `GET /oauth2-redirect.html`, `/flasgger_static/*`.

The public `insightsoftware.mintlify.app/.../openapi.json` is the Mintlify
"Plant Store" placeholder (2 paths). **Action for KB: publish the real spec.** A
copy is saved alongside this doc as `si-apispec-26.2.0.json`.

## 1. Endpoint inventory (● documented in Mintlify, ○ undocumented)

**Data — direct programmatic NLQ (all ○, and genuinely useful):**
- `POST /api/v1/data/query` and `/data/query/{source_id}` — RESTful NLQ that
  returns the **structured result directly** (no chat wrapper, no MCP, no SSE).
  Live-verified: `{"question":"How many alerts are there in total?"}` →
  `{"data":[{"current":{"count":1719,...}}]}`. This is the cleanest embed/automation
  path and it is completely absent from the user-facing API guide.
- `POST /data/query/stream`, `/data/query/{source_id}/stream` — SSE variants.
- `GET /data/suggestions[/{source_id}]` — suggested questions over REST.

**Agents — schema self-healing (○, "Experimental" tag):**
- `POST /api/v1/agents/data-source/repair/{source_id}/plan` — plan repair actions
  for a drifted source.
- `POST /api/v1/agents/data-source/repair/{source_id}/run` — execute them.
  This is the productised "Schema Change Detection" from the 25.4 notes, now with
  a real plan/run API. Undocumented beyond a one-line 25.4 mention.
- `POST /agents/data-source/run/{connection_id}` (streaming) alongside the known
  `…/run/task/{connection_id}` (async) — the streaming DSA variant is ○.

**Chat — conversational refine (○, "Experimental"):**
- `POST /api/v1/chat`, `/chat/refine`, `/chat/stream`, `/chat/stream/refine` —
  full conversational chat with history and **refine-a-previous-answer**. Only
  `chat/stream` is used by tooling in the wild; refine is undocumented.

**History — question memory, hybrid search, feedback (all ○):**
- `POST /api/v1/history/search` — **hybrid (semantic + keyword) search** over
  past questions. Required fields (from live 400): `search_text`, `data_source_id`.
- `GET /history/question/{id}/query-summary` — natural-language summary of a
  starred query.
- `PUT /history/question/{id}` — **upvote/downvote feedback** on an answer. Backed
  by table `question_records(question, start_vis, raw_data_populated, upvote,
  downvote, user_id, tenant_id, created_at)` — a built-in answer-quality feedback
  loop. Retention is env-tunable (see §3).

**Task (○ except the known stream):** `GET /task/status`, `/task/status/{id}`,
`/task/events/{id}` (non-stream) in addition to `…/events/stream/{id}`.

**System (mixed):** `GET /api/v1/version` (○), `POST /api/v1/auth/reset-trusted-access`
(○ — resets trusted-access tokens), `healthz` (●-ish).

**Documented and present as expected:** LLM Configurations (6), Rules (5),
File Analyzer (1), apikeys (3), the core auth endpoints.

## 2. MCP tool schemas (docs are wrong here)

Live `tools/list` inputSchemas vs the MCP Server Guide:
- `get_data(question*, source_id)` — ✔ matches.
- **`search_data_sources(search_subject, max_sources)`** — the guide calls this
  `get_data_sources` and omits `search_subject`. The real tool takes a search
  string. **Doc bug.**
- `get_suggested_questions(source_id, count)` — ✔.
- `get_field_statistics(source_id*, field_name)` — ✔.
`prompts/list` and `resources/list` are advertised but empty (tools-only).

## 3. Undocumented environment variables (live on the pods, absent from the ref)

- `DEBUG_MODE` — app debug toggle.
- `FIELD_VALUE_CACHE_BUDGET_MB` — memory budget for the field-value cache (the
  "raw cache" that made Amplifin's hardened source usable). A real tuning knob.
- `QUESTION_RECORD_RETENTION_DAYS` — how long question history is kept.
- `POSTGRES_HOST/PORT/USER/PASSWORD/DATABASE/EXTRA_ARGS` — the live chart wires DB
  via these, but the env-var reference documents `DB_HOST` / `MAIN_DB_URL` only.
- `COMPOSER_ADMIN_USERNAME`, `COMPOSER_ADMIN_PASSWORD` — service creds for the
  Composer/Discovery admin bind.
- `REDIS_PASSWORD` — documented reference lists `REDIS_URL` only.

## 4. Undocumented feature flag

`GET /api/v1/auth/features` → `{"bi_features_disabled": true}` on this instance
(licence-driven; ties to the `DISABLE_BI_FEATURES` licence bit). The endpoint is
the runtime feature-flag surface the SPA reads; only this one flag is exposed
today, and it is not documented.

## 5. Chart deltas 26.1.1 → 26.2.0 (feature-relevant)

- **MCP nginx sidecar removed** — FastMCP serves the well-known + OAuth endpoints
  itself on svc port **8001** (was proxied via nginx on 8000). `mcp.baseUrl`
  default moved to `http://localhost:8001` and derives every OAuth discovery URL.
- **`OLLAMA` is now a first-class LLM provider** (`GET /config/llm/providers`
  returns VERTEX_AI, AZURE_OPENAI, AWS_BEDROCK, **OLLAMA**) — native local models
  without the LiteLLM bridge. (Note: still no native OpenAI-direct or xAI; see the
  provider-findings doc.)
- **Discovery-proxy HPA + PodDisruptionBudget**, **Redis PDB**, Redis
  `pullPolicy: Always` — new HA/ops surface (`autoscaling`, `podDisruptionBudget`
  blocks under `simba.intelligence.*`).
- **`managedUrl`** value added — point SI auth at a Logi Symphony managed URL
  instead of Composer auth.

## Update 2026-07-11 — cross-checked against official sources
The official v26.2.0 release notes (Confluence PJX/18483511372) and Jira project PY (fixVersion v26.2.0) were located and reconciled with these findings. Corrections:
1. `search_data_sources` is the **intended** replacement for `get_data_sources` (PY-487), not a doc bug.
2. The streaming `POST /agents/data-source/run/{connection_id}` is **deprecated** in favour of the async task endpoint (PY-560).
3. 26.2 **auto-wipes tenant-scoped vector indexes when embeddings change** (PY-557), de-risking an embeddings-provider switch.
See `26.2-authoritative.md` (full reconciliation) and `26.2-release-notes-official.md` (mirrored official notes).
